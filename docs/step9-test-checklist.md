# 第 9 步测试清单（滚动登记）

> 图例：✅ 已验证 ／ ⬜ 未验证 ／ ➖ 不适用

## 阻塞项（没绿不能发版）

- ⬜ **澎湃 OS 五个手动设置全部打开后，户外 1 小时记录不中断**
      五个设置的操作说明见 `docs/hyperos-setup.md`。
      验证方式：按说明设置好，户外走/骑 1 小时，中途锁屏，回来检查轨迹是否连续。
      **这条必须你本人出门做，我无法代做。**

- ✅ **进程被杀后恢复**
      实测（2026-11-16 21:20）：记录中 `am force-stop` 杀进程 → 重新打开 App，
      界面显示「已结束旧行程，可以重新开始」，数据库里该行程状态为 `FINISHED`、
      `endedAt` 已写入，没有残留 `RECORDING`，也没有出现两条并行行程。
      注：当前策略是**结束**而不是**继续**——暂停后 GPS 断档再续，
      会产生一条横穿城市的直线，比结束更难解释。

- ✅ **拆分中途人为制造校验失败，确认三段数据全部回滚**
      实测（2026-11-16 21:19）：删掉停留行制造「点未被覆盖」状态 →
      在第 2 段上执行拆分 → 弹出「操作没有生效：分段校验失败：POINT_NOT_COVERED(点 seq=62…)」
      → 查库确认分段仍是 `0..61 / 77..106 / 107..164` 三段，与失败前逐字段一致，
      没有留下半拆状态，原始 165 个轨迹点也没动。

## 来自第 4 步

- ⬜ 设置 → 显示瞬时速度：打开后室外验证
      1. 正常走路，速度应稳定在 3~6 km/h，不在 0 和 30 之间乱跳
      2. 站着不动 6~8 秒，应显示「静止」
      3. 再走起来，立刻恢复数字
      4. 室内无星时应显示「等待定位」（已验：室内确实显示等待定位）
- ⬜ `Tuning.SpeedDisplay.WINDOW_SIZE` 可能偏小（当前 5），若上面第 1 条跳动明显，调到 7 再测
- ⬜ 行程数量变多（50+）后列表页是否卡顿（现在是 N+1 查询）
