## 4.2 地图接口的扩展

原来的 `MapController` 只有 `render(scene)`，它内部 `map.clear()` 全量重画。
回放时每移动一次光标就重建整条轨迹，拖动滑块会明显卡。

所以拆成两个原语：

```kotlin
fun renderTrack(polylines: List<MapPolyline>)  // 逐条 remove，不做 map.clear()
fun renderCursor(point: Wgs84?)                // 只换一个标记
```

`render(scene)` 保留（演示页在用），内部改为调用这两个。
这是**接口的破坏性变更**——不过目前只有高德一个实现，影响面为零。

## 4.6 新增：瞬时速度显示

### 设计

| 环节 | 做法 | 位置 |
|---|---|---|
| 取数 | 优先系统 `Location.speed`；为 null 时回退「上一点→当前点 距离/时间」 | `SpeedSampler` |
| 过滤 | `accuracy > MAX_ACCURACY_M` 的点不产生样本（也不参与距离/时间） | `SpeedSampler` |
| 平滑 | 最近 5 个样本的中位数（不是均值，单次跳点带不偏） | `SpeedSmoother` |
| 静止 | 低于 0.5 m/s 且持续 ≥ 5 秒 | `SpeedSmoother` |
| 单位 | 内部一律 m/s，展示转 km/h 保留一位小数 | `Fmt.speed` |

参数全部集中在 `Tuning.SpeedDisplay`：`WINDOW_SIZE=5`、`STATIONARY_SPEED_MPS=0.5`、`STATIONARY_HOLD_MS=5000`。

**一个刻意的非对称设计**：进入静止要谨慎（连续 5 秒），离开静止要灵敏（本次原始样本一达到阈值就解除）。
原因：只按中位数退出的话，窗口里旧的低速样本会把中位数压住十几秒——用户已经走起来了，
界面还显示「静止」。这个行为是单测先发现的，不是事后补的。

### 和着色的关系

- 显示：平滑后的值
- 地图「按速度着色」：`TrackPainter` 里的原始值，一行代码都没改

两者不共享状态，互不影响。

### 单测 17 个（全过）

```

```

覆盖：中位数（奇/偶/空）、单次 40 m/s 跳点不带偏、窗口滑动、静止 4 秒不判/5 秒判、
回升立即解除、解除后重新计时、reset 清空、取数优先级、回退距离时间、精度过滤、
无上一点、时间差过小、离线序列断点重新开窗、精度差点输出空。

## 4.7 瞬时速度：改为设置开关（默认关闭）

**2026-11-16 修正**：之前理解成「从 UI 删除」，实际需求是「暂时不显示，等室外验证后再看」。
现在改成设置项，代码和数据都保留。

| 项 | 行为 |
|---|---|
| 设置页开关「显示瞬时速度」 | 默认 **关闭** |
| 关闭时 | 记录页、详情页回放都不显示速度（与删除前一致） |
| 打开时 | 记录页显示实时速度；详情页回放显示该时刻速度 |
| 无定位样本时 | 显示「等待定位」，**不显示 0.0** |
| 数据来源 | SpeedDisplay.kt 的取样 + 中位数平滑 + 静止判定，没有第二套实现 |

引擎侧采样一直没有停：RecordingService.processFix 仍在算 RecordingUiState.speedMps，
开关只是决定要不要渲染。
